# Tune UI polish — 21 October 2026

Implemented on `codex/tune-ui-polish-20261021`, based on
`041cb2a8e91d86f7a747d8b5655826ba43326ee5` from `claude/tune-core-hardening-20261019`.
The original checkout and its uncommitted work were left intact. This is a local source change;
it does not update an installed copy, publish a release, or merge the branch.

## Result

Tune keeps its green accent, pearl background, glass surfaces, logo and animated navigation.
Original font sizes, quieter borders and shadows, wider spacing and consistent row padding reduce visual
density. Secondary explanations use a shared native `DetailsDisclosure`, with keyboard support and
contextual accessible names. Error states, missing measurements, action progress and critical
warnings remain visible. Both English and Hebrew/RTL are implemented.

No Electron runtime, IPC contract, system operation, service or licensing policy was changed.
No dependency or product version was changed. The renderer still obeys the existing architecture
rules, including presentation-only shared components.

The overview no longer labels unknown recommendations as “All OK”. A failed current cleanup or
startup scan shows an unavailable headline while retaining the prior list with its explanation.
A stale live sensor cannot revive an older successful temperature from the performance snapshot.
Three renderer regression tests cover these cases.

### Font-size correction

At the owner's request, the follow-up restores the font sizes from the base renderer, including
body text, rows, metadata, statistics, headings, navigation and footer. Shared spacing and native
disclosures remain. New secondary detail text follows the original metadata size; Settings help
follows its original row-meta size.

After this CSS-only correction, the build, all 95 UI checks and all 24 layout checks passed again. A one-off renderer probe
also compared computed font sizes against the base stylesheets on the same DOM: Updates, Overview,
Performance, Performance center and Settings, at both tested window sizes (10 comparisons, all
matching). The earlier unit/licensing results below precede this font-only correction.

The UI suite uses the real renderer, preload and IPC dispatch with synthetic Windows scan results.
It verifies native details by mouse and keyboard, expanded bounds, no renderer errors, failed reads,
historical administrator-only boot measurements, and the existing startup/recommendation/driver/
GPU/BIOS/device/cleanup/restore callbacks. Both hardware exports are checked as actual files under
its temporary sample download directory. Every machine-changing operation is replaced before the
app loads, and service-pipe connections are refused. No real cleanup, driver installation, startup
change, restore point, service installation or privilege prompt was run.

Layout checks exclude the unpainted contents of closed native disclosures; their visible summaries
remain checked. The UI suite separately opens disclosures and checks the content and expanded
bounds. The celebration and failed-scan fixtures now provide deterministic healthy input for
sources they do not vary, rather than relying on PowerShell on the host. Their assertions remain.

Synthetic screenshots are written to `e2e/output/ui-polish/after/`. Equivalent baseline frames from
the unchanged base renderer are in `before/`. They are local ignored evidence, not user data.
The base-renderer run reported one small-window sidebar overflow case; the final run reports none.

Reproduce after building, using a local Electron binary:

```sh
ELECTRON_DISABLE_SANDBOX=1 node_modules/.bin/electron \
  --no-sandbox --ozone-platform=headless --ozone-override-screen-size=1920,1080 --disable-gpu \
  e2e/headless-run.cjs e2e/ui-polish.cjs
```

Replace the last entry point to run the other Electron suites listed above. The Windows CI workflow
also includes `npm run e2e:ui-polish`; that new CI step has not run because this branch was not pushed.

| TUN-01 | LocalSystem pipe authorization | **Fixed (administrator rule), validated on the CI VM** | read-only requests (version, sensors) stay open to users signed in at the PC; a change runs only when the caller's token has the local Administrators group, enabled or UAC "deny only"; a standard user is refused (`notAllowed`) and Tune falls back to Windows' own prompt. | TUN-12 | Service upgrade not recoverable | **Fixed, validated on the CI VM** | each install goes into its own version folder; the service switches only if the new version then answers, otherwise it goes back to the previous one; the previous folder is kept for one more update; one version number (`privilege/service-version.cjs`); a failed removal is reported by the uninstaller. CI: an update side by side; an update whose service never starts rolled back; the published 1.3.1 upgraded both as an automatic update and by running the new installer over it. After an automatic update (review WIN-R03) the app never sends a change to the older service: only the version it was built with runs changes, anything else (older, unverifiable, missing) goes through Windows' prompt; the update is offered at once (a notice with Update or Later) and Settings keeps a reminder until the new version answers. Remaining: that routing doesn't repair the old service, which keeps running, without the TUN-01/06 fixes, and can still be asked by other programs on the PC until the user updates it; the real prompt after a real automatic update is checked by hand (`docs/windows-validation.md`) |

Tests prove forbidden hosts receive zero requests. CAB extraction is asynchronous with a timeout. Privileged process lifecycle: TUN-06. |
